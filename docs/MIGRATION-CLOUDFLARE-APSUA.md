# Перенос «Апсуа Тур» на собственный Cloudflare

**Статус: подготовка, не готово к публикации.** Рабочий ChatGPT Sites `apsua-tour-design` не менять. Эта ветка создана для самостоятельного Worker и не должна мержиться в `main` без полной проверки. Текущий исходник использует Sites-managed D1 и R2, поэтому один GitHub-код **не содержит** живые заявки/профили/загрузки.

## Уже создано в аккаунте владельца (по скриншотам 03.11.2026)

- Домен: `apsuatur.com` (настроен в Cloudflare, **ещё не связан с продуктивным Worker**).
- Новая пустая D1: `apsuatur-db` (0 таблиц до импорта).
- Новая пустая R2: `apsuatur-media` (0 байт, публичный доступ отключён).
- Старый Worker `apsua-tour-demo` не менять, не считать продуктивным.
- Новый Worker планируется как `apsuatur-prod`, **ещё не создан и не задеплоен**.

## Что делает эта ветка

Установка переменной `APSUA_SELF_HOSTED=1` перед `npm run build` включает имя нового Worker и bindings `DB`/`BUCKET` для собственной Cloudflare. Не указывать флаг: прежняя Sites-сборка остаётся прежней. Самостоятельный Worker удаляет все пришедшие от клиента заголовки `oai-authenticated-user-*` до передачи запросов API/Next, чтобы пользователь не мог подделать владельца. Не включать вход по ChatGPT на стороннем домене: Sites обеспечивает доверие к этим заголовкам только на собственной площадке. В новом Worker нужны проверенная авторизация Telegram и ранее корректно выданные роли администраторов или отдельная процедура первоначального назначения владельца.

## Обязательные блокеры до первого боевого запуска

1. Сделать **полный разрешённый экспорт оригинальной D1**: схема и все таблицы, особенно `settings`, `records`, `views`, `votes`. Админский экспорт каталога не заменяет SQL-дамп. Доступ из личного Cloudflare аккаунта к Sites-managed D1 не подразумевается. Если доступ отсутствует, подготовить однократный защищённый серверный экспорт в текущем Sites проекте, но не делать публичный endpoint.
2. Сделать копию всех оригинальных объектов R2 с исходными ключами, HTTP metadata и типами. Без этого `/api/media/<uuid>` начнёт отвечать 404 для старых изображений.
3. Выяснить способ назначения нового Telegram-администратора, не подделывая заголовки; проверить сохранение учётных записей и ролей после миграции.
4. Вручную восстановить **секреты** Worker (Telegram, VAPID, диспетчерская, платёжный webhook при необходимости) через Cloudflare Secrets. Не выкладывать токены ни в GitHub, ни в архивы, ни в чат.
5. Запустить полную CI-проверку из `START-HERE.md`, выполнить аудит безопасности авторизации и проверить сценарии пользователя в отдельном тестовом Workers URL.
6. Непосредственно перед сменой домена сделать финальную синхронизацию базы/медиа и обеспечить, чтобы новые заявки больше не записывались параллельно в старое хранилище.

## Локальная проверка production-конфигурации (PowerShell)

```powershell
npm ci
$env:APSUA_SELF_HOSTED = '1'
$env:APSUA_WORKER_NAME = 'apsuatur-prod'
$env:APSUA_D1_DATABASE_NAME = 'apsuatur-db'
$env:APSUA_R2_BUCKET_NAME = 'apsuatur-media'
$env:APSUA_D1_DATABASE_ID = '<UUID из Cloudflare D1 Overview>'
npm run build
node scripts/check-self-hosted-build.mjs
npx tsc --noEmit
```

**Не запускать пока `wrangler deploy`**: сначала перенос живых данных и проверки. Не ставить настоящие данные в локальную D1 из `lib/site-seed.json`: это только начальные каталожные данные, не замена продакшену.

В будущем после полного переноса деплой планируется через `npx wrangler deploy --config dist/server/wrangler.json` в отдельный Worker `apsuatur-prod`, затем `apsuatur.com` как Custom Domain. Настроить `www` при необходимости. Для регулярных релизов добавить ручной контролируемый GitHub Actions workflow, позже согласовать автоматизацию после PR.

## Что делать владельцу сейчас

В Cloudflare больше ничего не создавать. Определить способ полного экспорта данных из старого проекта ChatGPT Sites. Новый D1 и R2 должны оставаться пустыми до проверенного импорта. Исходную площадку не выключать.

## Дополнение 3 ноября: готовый офлайн-пакет для импорта

Создан и полностью проверен локально архив `APSUA-TUR-CLOUDFLARE-IMPORT-READY-2026-11-03.zip`. **Архив содержит настоящие персональные данные и не должен попадать в GitHub.** Внутри совместимый с Cloudflare D1 SQL, 74 проверенных медиафайла R2, манифест, Python-скрипты проверки/импорта и подробная инструкция `migration-tools/docs/SELF-HOSTED-RESTORE-RU.md`.

Исходный SQL содержит `BEGIN TRANSACTION`, `COMMIT`, `PRAGMA foreign_keys=OFF` и прямые операции с `sqlite_sequence`. В совместимом SQL они исключены. Преобразованный SQL успешно восстановлен в чистую SQLite; значения **всех таблиц** совпали с оригинальной физической копией. В отчёте: 498 строк, R2 74 объекта / 22 180 366 байт, SHA-256 всех объектов совпадает. Новый D1 **ещё не импортирован**, R2 **ещё не импортирован**: отсутствует прямой доступ к личному Cloudflare аккаунту владельца.

На самостоятельном Worker заголовки `oai-authenticated-user-*` удаляются как недоверенные. Для полномочий владельца добавить Cloudflare secret `SITE_OWNER_TELEGRAM_ID` с проверенным ID формата `tg:<id>` (или `tg:oidc:<hash>` при соответствующей проверенной личности). Только валидная Telegram-сессия с точно совпадающим ID получает владельческие права. Не выводить этот идентификатор в публичный репозиторий. Старые права владельца ChatGPT Sites на новом хостинге не действуют.

Импорт в новый аккаунт Cloudflare выполнить сначала на отдельной пустой D1; до публикации необходимо всё протестировать и сделать **финальную синхронизацию** после 3 ноября (новые заявки продолжают записываться в старый Sites). Публикацию `apsuatur.com` пока не выполнять.
