# Облачный перенос «Апсуа Тур» (без PowerShell и локальных программ)

**Статус:** механизм подготовлен в черновом PR. Пока пользователь не подключит свой Cloudflare к GitHub Actions и не положит архив в приватный R2, удалённый импорт физически невозможен. Это не означает, что данные уже перенесены.

## Архитектура
- Старый рабочий сайт ChatGPT Sites v182 работает без изменений.
- Новый Cloudflare: домен `apsuatur.com`, D1 `apsuatur-db`, R2 `apsuatur-media`.
- Пакет: `APSUA-TUR-CLOUDFLARE-IMPORT-READY-2026-11-03.zip` (проверенный архив, 498 записей D1, 74 объекта R2).
- Данные **никогда не публикуются в GitHub**: GitHub Actions временно скачивает приватный архив из R2 в память одноразового runner, сверяет контрольные суммы и делает импорт. Runner автоматически уничтожается после выполнения; Actions artifacts не создаются.
- Исполнитель ограничен вручную запускаемым workflow `Apsua Cloudflare migration (manual only)`, никаких автоматических `push` или `pull_request` запусков импорта нет. Ветка должна пройти проверки и попасть в `main` до того, как этот workflow станет доступен кнопкой Run workflow.

## Однократные действия владельца через браузер

### 1. Закрытое промежуточное хранение (одна загрузка ZIP)
В Cloudflare Dashboard открой Storage & databases → R2 → `apsuatur-media`.
В приватном bucket создай каталог `_migration` и **загрузи в него файл** `APSUA-TUR-CLOUDFLARE-IMPORT-READY-2026-11-03.zip`.
Итоговый ключ должен быть ТОЧНО:
`_migration/APSUA-TUR-CLOUDFLARE-IMPORT-READY-2026-11-03.zip`.
Этот архив содержит реальные личные данные. **Публичный доступ к R2 НЕ включать.** Не выкладывать ZIP, SQL, медиа, манифест в публичный GitHub или на общедоступную ссылку.

### 2. Выдать временные полномочия (только в настройках, не в чате)
В Cloudflare создать scoped API Token для D1 (чтение/редактирование нужной базы) и отдельный R2 S3-compatible API Token с Object Read & Write для `apsuatur-media`. Важно не использовать Global API Key и не выдавать доступ ко всем бакетам. Из Cloudflare Dashboard взять Account ID (32 hex) и UUID базы `apsuatur-db`.

На странице GitHub `daad775-art/apsua-tour` → Settings → Secrets and variables → Actions → New repository secret занести **пять значений**:
- `CLOUDFLARE_ACCOUNT_ID` — Cloudflare Account ID.
- `CLOUDFLARE_API_TOKEN` — токен Cloudflare с D1 Read/Write к ресурсу.
- `APSUA_D1_DATABASE_ID` — UUID только новой `apsuatur-db`.
- `APSUA_R2_ACCESS_KEY_ID` — R2 S3 Access Key ID.
- `APSUA_R2_SECRET_ACCESS_KEY` — R2 S3 Secret Access Key.

Не присылать секреты, cookie, SQL или пользовательские данные в ChatGPT. После переноса временные токены отозвать. Для будущих деплоев настроить отдельный ограниченный токен.

### 3. Запуск проверки без записи
После безопасного слияния PR в `main`: GitHub → Actions → **Apsua Cloudflare migration (manual only)** → Run workflow:
- `mode = verify` (по умолчанию);
- `confirmation` оставить пустым.

Проверка читает ZIP напрямую из приватного R2, проверяет SHA-256 ZIP, SQL, каждого R2-файла, пробует восстановить SQL в памяти на runner, затем проверяет, что Cloudflare D1 имеет имя `apsuatur-db` и не содержит чужих таблиц. **Ни одной записи в D1/R2 не создаётся.**

### 4. Запуск импорта в пустую базу
Только после зелёной проверки запусти тот же workflow с:
- `mode = restore`;
- `confirmation = RESTORE-APSUA-498-74`.

Алгоритм: проверка архива → проверка целевой D1 и R2 → загрузка/сверка всех 74 медиафайлов в R2 → импорт SQL в пустую D1 → сверка записей. Если в базе есть другие данные, сервис откажется менять её. Повторный слепой импорт запрещён. Если загрузка оборвётся на R2, следующая попытка проверит существующие файлы и продолжит. Если D1 уже содержит данные, импорт повторно запрещён.

### 5. Что ещё НЕ делает этот workflow
- Не переносит автоматически новые заявки, появившиеся **после 3 ноября** на старом сайте. Перед публичным запуском нужен финальный свежий экспорт и синхронизация.
- Не разворачивает сам Worker и не меняет DNS/домен.
- Не устанавливает Telegram-секреты, не подтверждает права администратора.
- Не превращает `workers.dev` в закрытый тестовый адрес. Для теста отдельно нужно Cloudflare Access или аналогичная защита.
- Не удаляет промежуточный ZIP в R2 автоматически; после полного завершения владелец должен удалить его вручную и отозвать временные ключи.

## Безопасность
Никаких публичных backup URL, никаких вложений с персональными данными в Issues/PR/Artifacts. GitHub Actions runner сторонний сервис, хотя среда эфемерна: удалённый импорт означает временную обработку резервной копии в GitHub Actions. Если это недопустимо для персональных данных, выбрать прямую миграцию с помощью защищённого Cloudflare Worker вместо GitHub Actions.

**Примечание:** Архив доступен пользователю из ChatGPT Library, но GitHub Actions не имеет доступа к его приватной библиотеке. Поэтому один перенос архива в закрытый R2 требуется, если нет отдельно подключённого приложения с прямым доступом к Cloudflare.
