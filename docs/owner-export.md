# Временный экспорт владельца

Экспорт предназначен только для переноса действующей D1 и R2 на аккаунт владельца. Он выключен по умолчанию и не меняет данные.

## Защита

Для доступа одновременно требуются:

1. действующая сессия владельца сайта;
2. запрос с того же origin;
3. `OWNER_EXPORT_ENABLED=1` в окружении Worker;
4. секрет `OWNER_EXPORT_TOKEN` в окружении Worker и заголовке `X-Apsua-Export-Token`.

Секрет нельзя помещать в репозиторий, URL, команды или логи. После успешного переноса удалите обе переменные и сам временный экспорт отдельным PR.

## Ограничение D1

`D1Database.dump()` поддерживает только базы, созданные во время alpha-периода D1. Для современной базы экспорт строится логически: схема читается из `sqlite_schema`, значения — страницами. Тип хранения каждого значения сохраняется отдельно; `INTEGER` передаётся строкой, `BLOB` — шестнадцатеричной строкой, чтобы JavaScript не исказил данные.

Единого снимка на несколько HTTP-запросов Worker Binding API не предоставляет. Скрипт выполняет два полных прохода и сравнивает SHA-256. Если база изменилась во время копирования, экспорт прекращается. Для гарантированного атомарного снимка при постоянной записи нужен штатный `wrangler d1 export`/Cloudflare API либо экспорт силами поддержки платформы.

## Запуск после отдельного разрешения на публикацию

Перед запуском задайте переменные окружения локально, не записывая их в shell history:

```text
APSUA_EXPORT_ORIGIN=https://apsua-tour-design.rkviii.chatgpt.site
APSUA_EXPORT_COOKIE=<Cookie действующей сессии владельца>
APSUA_EXPORT_TOKEN=<тот же временный секрет>
APSUA_EXPORT_DIR=./private-backup
```

Запуск:

```text
node scripts/export-owner-backup.mjs
```

Результат содержит `d1-export.sql`, объекты R2 под безопасными локальными именами, `manifest.json` с исходными ключами и метаданными и `report.json` с количеством строк/файлов и контрольными суммами.
